# Словарь данных (Data Dictionary)

Документ описывает структуру базы данных, типы данных, ограничения и назначение каждого поля. Используется для однозначного понимания требований между аналитиком и командой разработки.

## 1. Таблица `users` (Пользователи)
Хранит информацию о сотрудниках, которые могут бронировать комнаты.

| Поле | Тип данных | Обязательное | Ограничения | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `id` | SERIAL | Да | PRIMARY KEY | Уникальный идентификатор пользователя |
| `full_name` | VARCHAR(255) | Да | — | Полное имя сотрудника |
| `email` | VARCHAR(255) | Да | UNIQUE | Рабочая почта (используется как логин) |
| `is_active` | BOOLEAN | Да | DEFAULT TRUE | Флаг активности (уволенные сотрудники = FALSE) |

## 2. Таблица `rooms` (Переговорные комнаты)
Справочник доступных для бронирования помещений.

| Поле | Тип данных | Обязательное | Ограничения | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `id` | SERIAL | Да | PRIMARY KEY | Уникальный идентификатор комнаты |
| `name` | VARCHAR(100) | Да | — | Название переговорной (например, "Альфа") |
| `capacity` | INTEGER | Да | CHECK (capacity > 0) | Вместимость (количество человек) |
| `floor` | INTEGER | Да | — | Этаж, на котором находится комната |

## 3. Таблица `bookings` (Бронирования)
Основная таблица, фиксирующая факты бронирования комнат.

| Поле | Тип данных | Обязательное | Ограничения | Описание |
| :--- | :--- | :--- | :--- | :--- |
| `id` | SERIAL | Да | PRIMARY KEY | Уникальный идентификатор брони |
| `room_id` | INTEGER | Да | FOREIGN KEY (rooms.id) | Ссылка на забронированную комнату |
| `user_id` | INTEGER | Да | FOREIGN KEY (users.id) | Ссылка на пользователя, создавшего бронь |
| `start_time` | TIMESTAMP | Да | — | Дата и время начала встречи |
| `end_time` | TIMESTAMP | Да | CHECK (end_time > start_time) | Дата и время окончания встречи |
| `status` | VARCHAR(20) | Да | CHECK (status IN ('created', 'confirmed', 'cancelled')) | Текущий статус брони |
